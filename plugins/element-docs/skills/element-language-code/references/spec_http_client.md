# Спецификация HTTP-клиента Element 9.2

Сводная спецификация исходящих HTTP-запросов из серверного кода Element через `Стд::Http`. Составлена по HTML-документации и примерам из `data/temp/pages/http-client-stdlib`, `data/temp/pages/http-guide` и связанных материалов.

## Содержание

- Область действия
- Основные типы
- КлиентHttp
- ЗапросHttp
- ОтветHttp
- ЗаголовкиHttp и ЧитаемыеЗаголовкиHttp
- ПараметрыUrl
- Url
- АутентификацияHttp

- TLS и защищенные соединения
- Уровни настройки
- Практические паттерны
- Ограничения и инварианты
- Связь с JSON

## Область действия

Описано:

- создание и выполнение исходящих HTTP-запросов;
- URL, query-параметры, заголовки и body;
- аутентификация, прокси, таймауты, TLS;
- чтение HTTP-ответа.

Не описано:

- входящие HTTP-сервисы приложения (`HttpСервисЗапрос`, `HttpСервисОтвет`) как отдельная подсистема; ниже приведен только минимальный практический шаблон обработки входящего JSON/параметров;
- Console API как внешний REST API панели управления;
- SOAP-клиенты и интеграционная шина, кроме пересечений на уровне HTTP.

## КлиентHttp

В `Стд::Http` доступно свойство:

```xbsl
КлиентHttp: КлиентHttp
```

Базовый экземпляр используется как фабрика. Методы настройки возвращают новый `КлиентHttp`, а методы создания запроса возвращают `ЗапросHttp`.

### Свойства

| Свойство | Тип | Назначение |
|---|---|---|
| `Аутентификация` | `АутентификацияHttp?` | Аутентификация клиента. |
| `БазовыйUrl` | `Строка` | Базовый URL для относительных запросов. |
| `МаксимумПеренаправлений` | `Число` | Максимум redirect-переходов. |
| `Прокси` | `ИнтернетПрокси?` | Прокси-сервер. |
| `ТаймаутЗапроса` | `Длительность` | Максимальное время выполнения запроса. |
| `ТаймаутСоединения` | `Длительность` | Максимальное время установки соединения. |

### Создание запросов

Все стандартные методы принимают `Url: Url|Строка` и возвращают `ЗапросHttp`:

```xbsl
ЗапросGet(Url): ЗапросHttp
ЗапросPost(Url): ЗапросHttp
ЗапросPut(Url): ЗапросHttp
ЗапросPatch(Url): ЗапросHttp
ЗапросDelete(Url): ЗапросHttp
ЗапросHead(Url): ЗапросHttp
ЗапросOptions(Url): ЗапросHttp
ЗапросConnect(Url): ЗапросHttp
ЗапросTrace(Url): ЗапросHttp
```

Для нестандартного или динамического метода:

```xbsl
СоздатьЗапрос(Метод: Строка, Url: Url|Строка): ЗапросHttp
```

| `СТаймаутомЗапроса(Таймаут: Длительность): КлиентHttp` | Задает таймаут выполнения запроса. |
| `СТаймаутомСоединения(Таймаут: Длительность): КлиентHttp` | Задает таймаут соединения. |
| `СМаксимумомПеренаправлений(Количество: Число): КлиентHttp` | Задает максимум redirect-переходов. |

### URL-кодирование

`ЗапросHttp` и `Url` учитывают RFC 3986:

- корректные percent-encoded последовательности сохраняются;
- недопустимые символы и одиночный `%` кодируются;
- национальные символы в домене кодируются через IDN;
- национальные символы в пути/query/fragment кодируются percent encoding;
- разделители сегментов `:`, `/`, `?`, `#`, `[`, `]`, `@` и символы `-`, `.`, `_`, `~` не меняются.

## TLS и защищенные соединения

Клиент поддерживает обычный HTTPS/TLS, двусторонний TLS с сертификатом клиента и ГОСТ TLS через `СКриптоПроTls`.

```xbsl
КлиентHttp.СПараметрамиЗащиты(ПараметрыЗащищенногоСоединения)
КлиентHttp.СКриптоПроTls()
```

Для двустороннего TLS используются доверенные сертификаты сервера, клиентские ключи и пароль хранилища.

## Уровни настройки

| Уровень | Когда использовать |
|---|---|
| `КлиентHttp` | Общие настройки для группы запросов к одному API: базовый URL, auth, proxy, TLS, таймауты. |
| `ЗапросHttp` | Разовые отличия конкретного запроса: query, headers, body, override auth/proxy/timeouts. |
| `КонтекстHttp` | Значения, которые должны попасть только в конкретный вызов `Выполнить()`. |

Для нескольких серверов используйте отдельные настроенные экземпляры `КлиентHttp`.

## Практические паттерны

### JSON API через POST

HTTP-клиент не сериализует JSON сам: тело надо подготовить через `Стд::Json`, явно задать тип содержимого и после выполнения прочитать поток ответа.

```xbsl
знч Клиент = КлиентHttp.СПрокси(Прокси)
    .СБазовымUrl("https://api.example.com/v1/")
    .САутентификацией(Аутентификация)

исп ОтветХттп = Клиент
    .ЗапросPost("responses")
    .УстановитьТипСодержимого("application/json")
    .УстановитьЗаголовок("Authorization", "Bearer %{АпиКлюч.Раскрыть()}")
    .УстановитьТело(СериализацияJson.ЗаписатьОбъект(Запрос))
    .Выполнить()

знч КодСтатуса = ОтветХттп.КодСтатуса
знч ТелоОтвета = ОтветХттп.Тело.ПрочитатьКакСтроку()
```

Практически важные детали:

- относительный URL в `ЗапросPost("responses")` раскрывается через `СБазовымUrl(...)`;
- для `Content-Type` предпочтителен `УстановитьТипСодержимого("application/json")`; рабочий код также использует `УстановитьЗаголовок("Content-Type", "application/json")`;
- `ОтветHttp.Тело` читается как поток, поэтому ответ удобно держать в `исп`;
- HTTP-коды `4xx/5xx` проверяйте через `КодСтатуса` явно, не смешивая их с сетевыми исключениями.

### GET с query-параметрами

Для query-параметров используйте методы запроса, а не ручную склейку строки URL.

```xbsl
знч Запрос = КлиентHttp.СБазовымUrl("https://api.example.com/bot%{Токен}")
    .СПрокси(Прокси)
    .СПараметрамиЗащиты(новый ПараметрыЗащищенногоСоединения())
    .ЗапросGet("/sendMessage")
    .УстановитьПараметрЗапроса("chat_id", Адресат)
    .УстановитьПараметрЗапроса("text", Текст)

если ИспользоватьMarkdown
    Запрос.УстановитьПараметрЗапроса("parse_mode", "Markdown")
;

исп Ответ = Запрос.Выполнить()
знч ТелоОтвета = Ответ.Тело.ПрочитатьКакСтроку()
```

`УстановитьПараметрЗапроса` заменяет значение параметра. Если нужен параметр с несколькими значениями, используйте `ДобавитьПараметрЗапроса`.

### Формирование внешней ссылки с query string

`ПараметрыUrl` полезен и вне `ЗапросHttp`, когда нужно собрать ссылку для перехода во внешний сервис.

```xbsl
знч Параметры = <Строка, Строка>{:}
Параметры.Вставить("MNT_ID", Счет)
Параметры.Вставить("MNT_AMOUNT", Сумма.ВСтроку())
Параметры.Вставить("MNT_DESCRIPTION", Описание)

знч Ссылка = "https://pay.example/checkout" + новый ПараметрыUrl(Параметры).ВСтроку()
```

Для уже исполняемого запроса предпочтительнее `ЗапросHttp.УстановитьПараметрЗапроса(...)`, потому что кодирование и объединение с базовым URL делает HTTP-клиент.

### Минимальный входящий HTTP-сервис

Входящие сервисы не относятся к `Стд::Http`, но часто находятся рядом с HTTP-клиентами и JSON-кодом. Рабочий шаблон:

```xbsl
метод ЗапросPOSTОбработкаЗапроса(Запрос: HttpСервисЗапрос)
    знч ТелоСтрокой = Запрос.Тело.ПрочитатьКакСтроку()
    знч Ид = Запрос.Параметры.ПолучитьПервый("id")
    знч Токен = Запрос.Заголовки.ПолучитьПервый("Authorization")?.Заменить("Bearer ", "") ?? ""

    если Токен.Пусто()
        Запрос.Ответ.УстановитьКодСтатуса(403)
        возврат
    ;

    знч Данные = СериализацияJson.ПрочитатьОбъект(ТелоСтрокой, Тип<Соответствие<Строка, Объект?>>)
    знч Ответ = {"ok": Истина, "id": Ид, "method": Данные.ПолучитьИлиУмолчание("method", "")}

    Запрос.Ответ.Заголовки.Установить("Content-Type", "application/json")
    Запрос.Ответ.УстановитьТело(СериализацияJson.ЗаписатьОбъект(Ответ))
;
```

Для ошибок до разбора тела сначала выставляйте код статуса и возвращайтесь без попытки записать невалидный JSON-ответ, если контракт сервиса этого не требует.

### HTTP-ссылки на двоичные объекты

Для передачи файла или изображения во внешний API можно создать временную публичную ссылку на двоичный объект и положить ее в JSON:

```xbsl
знч Ссылка = Изображение.СоздатьHttpСсылку(Неопределено, ТребуетсяАутентификация = Ложь).Абсолютная("")

знч Сообщение = {
    "type": "input_image",
    "image_url": Ссылка
}
```

Это не часть `Стд::Http`, но это рабочий способ связать объектное хранилище, HTTP-доступ и JSON API.

## Ограничения и инварианты

- Все типы HTTP-клиента доступны на сервере.
- `ОтветHttp.Тело` является потоком чтения.
- URL нормализуется и кодируется платформой.
- JSON не сериализуется HTTP-клиентом автоматически.
- Для `Content-Type` используйте `УстановитьТипСодержимого(...)` или явно устанавливайте одноименный заголовок; не рассчитывайте на автоматический выбор по типу тела.

## Связь с JSON

Для JSON body используйте `Стд::Json`: сериализуйте объект в строку или поток, задайте `УстановитьТипСодержимого("application/json")`, передайте данные через `УстановитьТело(...)`, а `ОтветHttp.Тело` разбирайте через `СериализацияJson` или `ЧтениеJson`.
